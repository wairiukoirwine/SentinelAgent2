# SentinelAgent

**Design and Evaluation of a Policy-Enforced Security Gateway Against Indirect Prompt Injection in a Simulated AI Agent**
DAI034 Capstone · Track C (Secure AI Applications) · Africa International University, SCET
Team: Teddy Musyoki (lead developer), Irwine Kang'acha (design lead), Benedict Sau (detection lead) · Supervisor: Dr. Jared Mayeika

A simulated agent reads synthetic documents that may hide instructions, then proposes tool calls. Every call can pass through a **policy gateway** (ALLOW / BLOCK / REVIEW) and a **content detector** before any mock tool runs. Four setups are compared on the same 54 labelled scenarios. Everything runs locally: no real email, no network calls, no LLM API, no personal data.

## Quick start

Requirements: **Python 3.11+** and **Node.js 20+**. Works on Windows, macOS and Linux.

```bash
git clone <this repo> && cd SentinelAgent
python run.py setup     # creates backend/.venv and installs everything (first time only)
python run.py           # starts backend + dashboard
```

Open **http://127.0.0.1:5173** (dashboard). API docs: http://127.0.0.1:8000/docs. Stop with `Ctrl+C`.
On macOS/Linux use `python3` if `python` is not found.

| Command | What it does |
|---|---|
| `python run.py test` | Runs the 57 backend tests |
| `python run.py experiment` | Runs all four setups on all splits; writes `reports/evaluation_report.md` |
| `python run.py detector-eval` | Scores the detectors on the separate detector text sets; writes `reports/detector_report.md` |
| `python run.py ml-setup` | Optional: installs the pretrained detector (CPU torch + transformers) |
| `python run.py check` | Shows what is installed |

### In VS Code

1. **File → Open Folder…** and pick the repo folder. Accept the recommended extensions (Python, Pylance, debugpy, Claude Code).
2. **Terminal → Run Task… → SentinelAgent: Setup (first time)**.
3. **Ctrl+Shift+B** (default build task) starts the backend and dashboard.
4. Tests appear in the Testing panel. To debug, use the **Run and Debug** panel: "Backend: FastAPI (debug)", "Experiment CLI", "Pytest".
5. If VS Code asks for an interpreter, choose `backend/.venv` (Windows: `backend\.venv\Scripts\python.exe`).

### In Claude Code

Open the repo folder and start Claude Code. It reads `CLAUDE.md`, which holds the commands, file map and project rules (mock tools only, fail closed, never tune on the frozen final-test split, never invent results). Common commands are pre-approved in `.claude/settings.json`.

## The four setups

| ID | Detector | Gateway | Behaviour |
|---|:---:|:---:|---|
| A `baseline` | off | off | Intentionally unprotected. Every proposed mock action runs. |
| B `content_only` | on | off | Suspicious (or failed) detector result blocks the action; no policy rules. |
| C `gateway_only` | off | on | Trusted task, allowlist and data-label rules decide ALLOW / BLOCK / REVIEW. |
| D `combined` | on | on | Detector result is passed to the gateway, which makes the final decision. |

REVIEW never runs until a separate recorded approval. In experiments, `--review-policy` chooses who answers: nobody (`pending`, default), a careless reviewer (`approve_all`), or a cautious one (`reject_all`).

## Results (final-test split, keyword detector)

Generated by `python run.py experiment` (run `experiment_34c8615a58e1`). Full report: [`reports/evaluation_report.md`](reports/evaluation_report.md). Raw rows: [`reports/results/`](reports/results/).

| Setup | Attack success | Normal completion | False blocks |
|---|---:|---:|---:|
| A Baseline | 100% (10/10) | 100% (7/7) | 0/4 |
| B Content check only | 70% (7/10) | 85.7% (6/7) | 1/4 |
| C Gateway only | 10% (1/10) | 85.7% (6/7) | 0/4 |
| D Combined | 10% (1/10) | 71.4% (5/7) | 0/4 |

The gateway stops every redirect attack, including misspelled, spaced, leetspeak, base64 and Swahili/French ones that the keyword detector does not flag. The one attack that gets through every setup is an **allowed-channel leak** (injected content inside an email the user really asked for), which recipient rules cannot see. The proposal predicted this limitation. Gateway setups hold some legitimate internal-data emails at REVIEW; a reviewer who approves them restores 100% normal completion. These are results on a small synthetic corpus with a simulated agent, not general claims.

**Detector (separate test set, 40 texts):** keyword baseline precision 100%, recall 10%. The pretrained classifier has **not** been evaluated yet; see below.

## Pretrained detector (Benedict)

The adapter for [`protectai/deberta-v3-base-prompt-injection-v2`](https://huggingface.co/protectai/deberta-v3-base-prompt-injection-v2) (Apache-2.0, CPU) is implemented and tested with a stand-in model, but the real model was not downloaded in the build environment. On a laptop with internet access:

```bash
python run.py ml-setup                         # ~1 GB download, once
python run.py detector-eval --pretrained       # picks a threshold on dev, scores test
# then run the experiment with the model as the detector:
SENTINELAGENT_DETECTOR=pretrained python run.py experiment        # macOS/Linux
$env:SENTINELAGENT_DETECTOR="pretrained"; python run.py experiment # Windows PowerShell
```

If the model cannot load, protected setups fail closed (BLOCK). `SENTINELAGENT_DETECTOR_FALLBACK=1` switches to the keyword detector and labels results "keyword-baseline (fallback)".

## Safety boundaries

- Synthetic documents only; all recipients are `@example.test` (enforced by the scenario loader and the mock email tool).
- Only two mock tools: `read_document` (scenario store, gated in C/D) and `send_email` (writes a SQLite row, `network_used: false`).
- Trusted task, allowlist, data label and attack labels live outside the document text and cannot be changed by it.
- Gateway, detector or input errors fail closed. Baseline is deliberately unprotected but still mock-only.
- The `final_test` split is frozen by hash; a test fails if it changes.

## Troubleshooting

- **`python` not found / wrong version:** install Python 3.11+; on Windows tick "Add to PATH"; on macOS/Linux use `python3`.
- **`npm` not found:** install Node.js 20+ and reopen the terminal.
- **Dashboard shows "API offline":** the backend is not running; use `python run.py`, not only `npm run dev`.
- **Port in use:** stop the other process on 8000/5173.
- **Start from an empty database:** delete `data/sentinelagent.sqlite3`, or set `SENTINELAGENT_DB` to another path.
- **PowerShell blocks scripts:** `run.py` needs no activation; the old `scripts/*.ps1` helpers still work if your policy allows them.
